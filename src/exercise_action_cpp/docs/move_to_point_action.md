# 题目二：二维移动机器人目标点导航

## 题目背景

移动机器人需要从当前位置沿直线移动到二维平面中的目标点。请实现一个有状态的动作服务端：客户端提交目标坐标和移动速度，服务端持续更新机器人位置，反馈剩余距离和任务进度，并支持在指定进度取消任务。任务成功或取消后，服务端都要保留机器人的最终位置，供下一个目标继续使用。

## 自定义动作接口

在 `base_interfaces/action/MoveToPoint.action` 中定义：

```text
float64 target_x
float64 target_y
float64 speed
---
bool success
string message
float64 final_x
float64 final_y
float64 traveled_distance
---
float64 current_x
float64 current_y
float64 remaining_distance
float32 progress
```

字段分为三部分：

| 部分 | 字段 | 含义 |
| --- | --- | --- |
| 目标 | `target_x`、`target_y` | 二维平面中的目标位置 |
| 目标 | `speed` | 机器人直线移动速度 |
| 结果 | `success` | 任务是否成功完成 |
| 结果 | `message` | 成功、取消或失败原因 |
| 结果 | `final_x`、`final_y` | 任务结束时的实际位置 |
| 结果 | `traveled_distance` | 本次任务已经移动的路程 |
| 反馈 | `current_x`、`current_y` | 机器人当前坐标 |
| 反馈 | `remaining_distance` | 当前点到目标点的剩余距离 |
| 反馈 | `progress` | 当前进度，范围为 `[0.0, 1.0]` |

## 通信设计

| 项目 | 名称 |
| --- | --- |
| 动作名称 | `/move_to_point` |
| C++ 服务端 | `move_to_point_server` |
| C++ 客户端 | `move_to_point_client` |
| Python 服务端 | `move_to_point_server` |
| Python 客户端 | `move_to_point_client` |
| 动作类型 | `base_interfaces/action/MoveToPoint` |

## 初始状态

服务端启动后，机器人位于坐标原点：

```text
current_x = 0.0
current_y = 0.0
```

当前位置属于服务端状态。正常完成或取消任务后不能自动回到原点，下一次任务必须从保留下来的位置开始。

## 目标校验规则

服务端收到目标后，必须依次检查：

1. `target_x`、`target_y` 和 `speed` 必须是有限数值。
2. `target_x` 和 `target_y` 必须位于 `[-10.0, 10.0]`。
3. `speed` 必须满足 `0.0 < speed <= 1.5`。
4. 当前点到目标点的距离必须大于或等于 `0.001`。
5. 任意条件不满足时拒绝目标，且不能修改当前位置。

二维距离按照下面的公式计算：

```text
distance = sqrt((target_x - current_x)^2 + (target_y - current_y)^2)
```

## 服务端执行要求

1. 记录任务开始位置并计算目标方向上的单位向量。
2. 每隔 `0.5` 秒更新一次位置，即反馈频率为 `2 Hz`。
3. 每次理论移动距离为：

```text
normal_step = speed * 0.5
```

4. 最后一步必须取理论移动距离和剩余距离中的较小值：

```text
actual_step = min(normal_step, remaining_distance)
```

5. 使用 `actual_step` 同时更新当前位置和累计路程，不能越过目标点。
6. 每次反馈都要填写当前位置、剩余距离和当前进度。
7. 进度按照累计路程除以本次任务总距离计算，最大值为 `1.0`。
8. 正常完成后将当前位置精确设置为目标坐标，并返回成功结果。

## 取消与状态保持

1. 服务端应当接受合法任务的取消请求。
2. 执行循环每次移动前检查任务是否已请求取消。
3. 取消后不能再多移动一步。
4. 取消结果中的 `success` 为 `false`。
5. `final_x`、`final_y` 和 `traveled_distance` 必须反映取消时的实际状态。
6. 取消位置应保存为新的当前位置，下一次任务从该位置继续。

## 客户端要求

客户端命令格式为：

```text
目标X坐标 目标Y坐标 移动速度 [取消进度百分比]
```

不取消任务：

```bash
ros2 run exercise_action_cpp move_to_point_client 3.0 4.0 1.0
ros2 run exercise_action_py move_to_point_client 3.0 4.0 1.0
```

在 `50%` 时请求取消：

```bash
ros2 run exercise_action_cpp move_to_point_client 4.0 0.0 1.0 50
ros2 run exercise_action_py move_to_point_client 4.0 0.0 1.0 50
```

客户端需要：

1. 检查命令行参数数量。
2. 将目标坐标、速度和可选取消进度转换为有限数值。
3. 取消进度必须位于 `[0, 100)`。
4. 等待动作服务端上线，并处理连接超时。
5. 异步发送目标并处理接受或拒绝结果。
6. 持续打印当前位置、剩余距离和进度。
7. 在达到指定进度后发送一次取消请求。
8. 根据 `SUCCEEDED`、`CANCELED` 和 `ABORTED` 区分最终状态。
9. 打印动作结果中的全部字段。

## 完整测试顺序

涉及初始位置的独立测试前需要重启服务端，使机器人回到 `(0.0, 0.0)`。

1. 提交 `(3.0, 4.0, 1.0)`，应成功到达 `(3.0, 4.0)`，移动路程为 `5.0`。
2. 不重启服务端，再提交 `(6.0, 8.0, 1.5)`，应从 `(3.0, 4.0)` 出发，移动路程仍为 `5.0`。
3. 再次提交 `(6.0, 8.0, 1.0)`，应因目标距离太小被拒绝。
4. 分别测试 `target_x` 和 `target_y` 超出 `[-10.0, 10.0]`，目标均应被拒绝。
5. 测试速度 `0.0`、负数和大于 `1.5`，目标均应被拒绝。
6. 测试目标距离 `0.0005`，应被拒绝；距离正好为 `0.001` 时应被接受。
7. 从原点提交 `(1.0, 0.0, 0.6)`，反馈位置应为 `0.3`、`0.6`、`0.9`、`1.0`，最后一步不能越过目标。
8. 从原点提交 `(-3.0, -4.0, 1.5)`，应正确处理负方向并返回路程 `5.0`。
9. 提交 `(10.0, -10.0, 1.5)`，应接受坐标和速度边界并成功到达目标。
10. 提交 `(4.0, 0.0, 1.0, 50)`，应在约 `50%` 时取消，结果位置为 `(2.0, 0.0)`，移动路程为 `2.0`。
11. 取消后不重启服务端，提交 `(2.0, 3.0, 1.5)`，应从 `(2.0, 0.0)` 继续移动。
12. 提交 `(4.0, 0.0, 1.0, 0)`，应在移动前立即取消，最终位置和路程均不变化。
13. 使用取消进度 `-1` 或 `100`，客户端应拒绝执行。
14. 任意数值参数为 `NaN`、`Inf` 或非法字符串时，客户端或服务端应安全拒绝。
15. 服务端未启动时，客户端等待超时后应给出明确提示并退出。

也可以使用命令行直接测试服务端：

```bash
ros2 action send_goal /move_to_point base_interfaces/action/MoveToPoint "{target_x: 3.0, target_y: 4.0, speed: 1.0}" --feedback
```

## 验收标准

- 坐标、速度、有限数和最小距离校验完整。
- 二维方向向量、当前位置、剩余距离和进度计算正确。
- 最后一步不会越过目标点。
- 正常完成和取消后都能正确保存当前位置。
- 取消结果中的最终位置和累计路程与实际运动一致。
- 客户端可以处理参数解析、连接、目标响应、反馈、取消和结果。
- C++ 与 Python 客户端、服务端可以交叉通信。
