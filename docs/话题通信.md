# ROS 2 话题通信总结

## 一句话理解

话题通信是一种**异步发布与订阅模型**：

- 发布方只负责向话题发送消息。
- 订阅方监听话题，并在消息到达时执行回调。
- 发布方不关心有没有订阅方，也不会等待订阅方返回结果。
- 同一个话题可以有多个发布方和多个订阅方。

它适合连续数据流，例如传感器数据、机器人状态、速度指令和定位结果。

## 核心组成

| 组成 | 作用 |
| --- | --- |
| Node | ROS 2 节点，发布方和订阅方都运行在节点中 |
| Topic | 消息传输通道，例如 `/scan`、`/cmd_vel` |
| Message | 消息的数据结构，例如 `std_msgs/msg/String` |
| Publisher | 向话题发布消息 |
| Subscription | 订阅话题并接收消息 |
| QoS | 控制消息缓存、可靠性和数据保留方式 |

发布方与订阅方能够通信，至少需要满足：

1. ROS Domain ID 兼容。
2. 话题名称相同。
3. 消息类型相同。
4. QoS 策略能够匹配。

## 通信特点

| 特点 | 说明 |
| --- | --- |
| 异步 | 发布方发送后不会等待订阅方处理 |
| 多对多 | 一个话题可以连接多个发布方和订阅方 |
| 无直接响应 | 订阅方不能通过同一次话题通信返回结果 |
| 松耦合 | 发布方通常不需要知道订阅方是否存在 |
| 适合连续数据 | 可以按照固定频率持续发布消息 |

如果业务要求“发送请求后必须得到一次明确结果”，应考虑服务通信；如果还需要进度和取消，应考虑动作通信。

## 消息接口

### 原生消息

ROS 2 已经提供常用消息，例如：

```text
std_msgs/msg/String
std_msgs/msg/Float32
geometry_msgs/msg/Twist
sensor_msgs/msg/LaserScan
nav_msgs/msg/Odometry
```

查看消息结构：

```bash
ros2 interface show std_msgs/msg/String
ros2 interface show geometry_msgs/msg/Twist
```

### 自定义消息

自定义消息文件使用 `.msg` 后缀，例如：

```text
# Student.msg
string name
int32 age
float64 height
```

接口功能包的 `CMakeLists.txt` 需要生成接口：

```cmake
find_package(rosidl_default_generators REQUIRED)

rosidl_generate_interfaces(${PROJECT_NAME}
  "msg/Student.msg"
)
```

`package.xml` 需要包含：

```xml
<buildtool_depend>ament_cmake</buildtool_depend>
<build_depend>rosidl_default_generators</build_depend>
<exec_depend>rosidl_default_runtime</exec_depend>
<member_of_group>rosidl_interface_packages</member_of_group>
```

修改接口后，应先重新构建接口功能包，再构建使用该接口的功能包。

## C++ 发布方

典型流程：

1. 继承 `rclcpp::Node`。
2. 使用 `create_publisher()` 创建发布方。
3. 创建定时器或在其他回调中准备消息。
4. 调用 `publish()` 发布消息。
5. 使用 `rclcpp::spin()` 持续处理定时器和回调。

```cpp
#include "rclcpp/rclcpp.hpp"
#include "std_msgs/msg/string.hpp"

using namespace std::chrono_literals;

class StringPublisher : public rclcpp::Node {
public:
    StringPublisher() : Node("string_publisher_cpp") {
        publisher_ = this->create_publisher<std_msgs::msg::String>(
            "string", 10
        );
        timer_ = this->create_wall_timer(
            1s,
            std::bind(&StringPublisher::timer_callback, this)
        );
    }

private:
    void timer_callback() {
        auto message = std_msgs::msg::String();
        message.data = "hello ROS 2";
        publisher_->publish(message);
    }

    rclcpp::Publisher<std_msgs::msg::String>::SharedPtr publisher_;
    rclcpp::TimerBase::SharedPtr timer_;
};
```

发布方和定时器需要保存为成员变量。局部变量离开作用域后被销毁，节点将无法继续发布。

## C++ 订阅方

```cpp
#include "rclcpp/rclcpp.hpp"
#include "std_msgs/msg/string.hpp"

using std::placeholders::_1;

class StringSubscriber : public rclcpp::Node {
public:
    StringSubscriber() : Node("string_subscriber_cpp") {
        subscription_ = this->create_subscription<std_msgs::msg::String>(
            "string",
            10,
            std::bind(&StringSubscriber::message_callback, this, _1)
        );
    }

private:
    void message_callback(
        const std_msgs::msg::String::SharedPtr message
    ) {
        RCLCPP_INFO(
            this->get_logger(),
            "收到消息: %s",
            message->data.c_str()
        );
    }

    rclcpp::Subscription<std_msgs::msg::String>::SharedPtr subscription_;
};
```

`_1` 表示订阅回调运行时传入的第一个参数，也就是收到的消息。

`SharedPtr` 是共享智能指针，可以管理消息对象的生命周期，并避免不必要的完整对象复制。

## Python 发布方

```python
import rclpy
from rclpy.node import Node
from std_msgs.msg import String


class StringPublisher(Node):
    def __init__(self):
        super().__init__("string_publisher_py")
        self.publisher_ = self.create_publisher(String, "string", 10)
        self.timer_ = self.create_timer(1.0, self.timer_callback)

    def timer_callback(self):
        message = String()
        message.data = "hello ROS 2"
        self.publisher_.publish(message)


def main():
    rclpy.init()
    node = StringPublisher()
    rclpy.spin(node)
    node.destroy_node()
    rclpy.shutdown()
```

## Python 订阅方

```python
import rclpy
from rclpy.node import Node
from std_msgs.msg import String


class StringSubscriber(Node):
    def __init__(self):
        super().__init__("string_subscriber_py")
        self.subscription_ = self.create_subscription(
            String,
            "string",
            self.message_callback,
            10
        )

    def message_callback(self, message: String):
        self.get_logger().info(f"收到消息: {message.data}")
```

Python 节点需要在 `setup.py` 的 `console_scripts` 中注册，才能通过 `ros2 run` 启动。

## QoS 基础

`create_publisher(..., 10)` 中的 `10` 表示 Keep Last 队列深度，不表示发布频率。

常见 QoS 维度：

| 策略 | 说明 |
| --- | --- |
| Reliability | `RELIABLE` 尽量保证送达，`BEST_EFFORT` 更关注实时性 |
| History | `KEEP_LAST` 保留最近数据，`KEEP_ALL` 尝试保留全部数据 |
| Depth | `KEEP_LAST` 模式下缓存多少条消息 |
| Durability | 是否让后加入的订阅方收到之前的数据 |

传感器数据通常使用适合实时数据的 Sensor Data QoS。发布方和订阅方 QoS 不兼容时，即使话题名称和类型正确，也可能收不到消息。

查看实际 QoS：

```bash
ros2 topic info /string --verbose
```

## C++ 构建配置

```cmake
find_package(rclcpp REQUIRED)
find_package(std_msgs REQUIRED)

add_executable(string_pub src/string_pub.cpp)
ament_target_dependencies(string_pub rclcpp std_msgs)

install(TARGETS
  string_pub
  DESTINATION lib/${PROJECT_NAME}
)
```

`package.xml` 中也要声明相同依赖：

```xml
<depend>rclcpp</depend>
<depend>std_msgs</depend>
```

```bash

```

## 常见问题

### 有节点但收不到消息

依次检查：

1. 是否执行了 `source install/setup.bash`。
2. 话题名称是否完全一致。
3. 消息类型是否一致。
4. 发布方是否真的调用了 `publish()`。
5. 订阅对象是否保存为成员变量。
6. 节点是否正在 `spin()`。
7. QoS 是否兼容。
8. 两个终端的 `ROS_DOMAIN_ID` 是否一致。

### 自定义消息头文件找不到

检查：

- 接口功能包是否成功构建。
- 当前终端是否重新加载环境。
- `CMakeLists.txt` 和 `package.xml` 是否声明接口依赖。
- 头文件名称是否使用小写下划线格式。

### 发布后订阅方没有立即收到第一条

DDS 发现需要一点时间。如果发布方启动后立刻只发布一次，订阅关系可能尚未建立。周期发布通常不会受影响；单次发布可以等待发现完成或使用合适的持久性 QoS。

## 复习清单

- 能解释发布方、订阅方、话题和消息之间的关系。
- 能使用原生消息完成发布与订阅。
- 能创建、生成并使用自定义 `.msg` 接口。
- 能说明定时器、`spin()` 和回调的作用。
- 能解释 C++ 回调中的 `_1` 和 `SharedPtr`。
- 能使用 ROS 2 命令检查话题、类型、频率和 QoS。
- 知道话题适合连续数据，不适合需要明确响应的业务。
