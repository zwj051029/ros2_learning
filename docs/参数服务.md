# ROS 2 参数服务总结

## 一句话理解

参数是**由节点拥有和管理的带类型配置项**。

例如：

```text
robot_name = delivery_robot
max_linear_speed = 1.0
safety_enabled = true
```

节点声明参数后，ROS 2 会自动为它提供参数查询和修改服务，因此不需要额外定义 `.msg`、`.srv` 或 `.action` 接口。

参数适合低频配置，不适合高频传感器数据或持续控制指令。

## ROS 2 参数模型

ROS 2 没有 ROS 1 那种独立的全局参数服务器。每个参数属于一个具体节点：

```text
/robot_config_server
    ├── robot_name
    ├── max_linear_speed
    └── safety_enabled
```

访问参数时需要同时知道节点名称和参数名称。

常见参数类型：

| ROS 2 参数类型 | C++ | Python |
| --- | --- | --- |
| bool | `bool` | `bool` |
| integer | `int64_t` | `int` |
| double | `double` | `float` |
| string | `std::string` | `str` |
| array | 对应类型的 `std::vector` | `list` 或 `array.array` |

Python 的 `float` 通常使用双精度浮点实现，对应 C++ 的 `double`。

## 声明参数

### C++

```cpp
this->declare_parameter("robot_name", "delivery_robot");
this->declare_parameter("max_linear_speed", 1.0);
this->declare_parameter("safety_enabled", true);
```

### Python

```python
self.declare_parameter("robot_name", "delivery_robot")
self.declare_parameter("max_linear_speed", 1.0)
self.declare_parameter("safety_enabled", True)
```

默认情况下，参数应先声明再访问或修改。

如果启用：

```cpp
rclcpp::NodeOptions().allow_undeclared_parameters(true)
```

或：

```python
super().__init__(
    "node_name",
    allow_undeclared_parameters=True
)
```

节点可以接受未提前声明的参数。但工程中通常推荐显式声明，便于发现拼写错误和维护参数类型。

## 查询参数

### C++

```cpp
auto parameter = this->get_parameter("max_linear_speed");
double speed = parameter.as_double();
```

批量查询：

```cpp
auto parameters = this->get_parameters(
    {"robot_name", "max_linear_speed"}
);
```

检查是否存在：

```cpp
bool exists = this->has_parameter("robot_name");
```

### Python

```python
parameter = self.get_parameter("max_linear_speed")
speed = parameter.value
```

批量查询：

```python
parameters = self.get_parameters([
    "robot_name",
    "max_linear_speed"
])
```

检查是否存在：

```python
exists = self.has_parameter("robot_name")
```

## 修改和删除参数

### C++

```cpp
this->set_parameter(
    rclcpp::Parameter("max_linear_speed", 1.5)
);
```

批量修改：

```cpp
this->set_parameters({
    rclcpp::Parameter("robot_name", "patrol_robot"),
    rclcpp::Parameter("max_linear_speed", 1.5)
});
```

删除参数：

```cpp
this->undeclare_parameter("temporary_parameter");
```

### Python

```python
from rclpy.parameter import Parameter

self.set_parameters([
    Parameter("robot_name", value="patrol_robot"),
    Parameter("max_linear_speed", value=1.5)
])
```

创建 `Parameter` 时建议显式使用 `value=`：

```python
Parameter("car_heights", value=2.0)
```

`Parameter("car_heights", 2.0)` 会把第二个位置参数当作参数类型，可能产生类型错误。

删除参数：

```python
self.undeclare_parameter("temporary_parameter")
```

## 参数修改回调

服务端可以在参数真正写入前检查新值。

### C++

```cpp
parameter_callback_handle_ =
    this->add_on_set_parameters_callback(
        std::bind(
            &RobotConfigServer::validate_parameters,
            this,
            std::placeholders::_1
        )
    );
```

```cpp
rcl_interfaces::msg::SetParametersResult validate_parameters(
    const std::vector<rclcpp::Parameter> &parameters
) {
    auto result =
        rcl_interfaces::msg::SetParametersResult();

    for (const auto &parameter : parameters) {
        if (
            parameter.get_name() == "max_linear_speed" &&
            parameter.as_double() <= 0.0
        ) {
            result.successful = false;
            result.reason = "最大线速度必须大于 0";
            return result;
        }
    }

    result.successful = true;
    return result;
}
```

C++ 返回的回调句柄需要保存为成员变量，否则回调可能被注销。

### Python

```python
self.add_on_set_parameters_callback(
    self.validate_parameters
)
```

```python
from rcl_interfaces.msg import SetParametersResult
from rclpy.parameter import Parameter


def validate_parameters(
    self,
    parameters: list[Parameter]
) -> SetParametersResult:
    for parameter in parameters:
        if parameter.name == "max_linear_speed":
            if parameter.type_ != Parameter.Type.DOUBLE:
                return SetParametersResult(
                    successful=False,
                    reason="最大线速度必须是浮点数"
                )

            if parameter.value <= 0.0:
                return SetParametersResult(
                    successful=False,
                    reason="最大线速度必须大于 0"
                )

    return SetParametersResult(successful=True)
```

参数修改回调应主要负责校验。不要在同一个校验回调中再次调用 `set_parameter()` 修改参数，否则可能造成递归调用或复杂的执行问题。

## 类型和有限数值检查

在读取具体值前先检查类型：

```cpp
if (
    parameter.get_type() !=
    rclcpp::ParameterType::PARAMETER_DOUBLE
) {
    return reject_parameter("参数必须是浮点数");
}
```

```python
if parameter.type_ != Parameter.Type.DOUBLE:
    return self.reject_parameter("参数必须是浮点数")
```

浮点参数还应检查：

```cpp
std::isfinite(value)
```

```python
math.isfinite(value)
```

这样可以拒绝 `NaN`、正无穷和负无穷。

命令行设置参数时，`1` 通常会被解析成整数，`1.0` 才会被解析成浮点数。已经声明为 double 的参数收到 integer 类型时可能被拒绝。

## 批量修改与原子修改

普通批量修改可能分别返回每个参数的处理结果：

```cpp
client_->set_parameters(parameters);
```

原子修改要求：

```text
全部参数合法：全部修改
任意参数非法：全部保持不变
```

C++ 同步参数客户端：

```cpp
auto result =
    client_->set_parameters_atomically(parameters);

if (!result.successful) {
    RCLCPP_ERROR(
        this->get_logger(),
        "修改失败: %s",
        result.reason.c_str()
    );
}
```

多个参数存在关联关系时，应优先使用原子修改。例如切换导航模式时，模式、速度和安全参数需要同时改变。

## 完整候选配置

参数回调收到的可能只是一部分参数。只检查请求中的新值并不一定正确。

假设当前配置：

```text
navigation_mode = standby
max_linear_speed = 0.0
```

请求只修改：

```text
navigation_mode = indoor
```

虽然 `indoor` 是合法模式，但修改后的完整配置中速度仍为 `0.0`，不符合室内运动规则。

正确流程：

1. 读取当前全部相关参数。
2. 复制为候选配置。
3. 用请求值覆盖候选配置对应字段。
4. 检查候选配置的类型、范围和参数关联。
5. 全部合法才接受原子修改。

```text
当前配置 + 请求中的变化
             ↓
        完整候选配置
             ↓
        统一合法性检查
             ↓
       接受或拒绝整次修改
```

这是编写复杂参数服务时最重要的思路之一。

## C++ 参数客户端

```cpp
client_ =
    std::make_shared<rclcpp::SyncParametersClient>(
        this,
        "robot_config_server_cpp"
    );
```

等待参数服务：

```cpp
while (!client_->wait_for_service(1s)) {
    if (!rclcpp::ok()) {
        return false;
    }
}
```

常用操作：

```cpp
client_->get_parameters(names);
client_->has_parameter(name);
client_->list_parameters({}, 0);
client_->set_parameters(parameters);
client_->set_parameters_atomically(parameters);
```

同步客户端使用方便，但会阻塞当前线程直到服务响应。不要在会造成执行器互相等待的回调中随意使用同步调用。

## Python 参数客户端说明

当前安装的 ROS 2 Humble 环境没有可直接导入的：

```python
rclpy.parameter_client.AsyncParameterClient
```

因此当前学习代码只实现 Python 参数服务端，并使用：

- `ros2 param` 命令。
- 节点自动提供的参数服务。
- C++ 参数客户端。

这不影响 Python 节点提供参数。参数查询和修改服务由节点自动创建。

## ROS 2 参数命令

查看参数列表：

```bash
ros2 param list /robot_config_server_cpp
```

查询参数：

```bash
ros2 param get \
  /robot_config_server_cpp \
  max_linear_speed
```

修改参数：

```bash
ros2 param set \
  /robot_config_server_cpp \
  max_linear_speed \
  1.5
```

查看参数描述：

```bash
ros2 param describe \
  /robot_config_server_cpp \
  max_linear_speed
```

导出和加载参数：

```bash
ros2 param dump /robot_config_server_cpp
ros2 param load /robot_config_server_cpp params.yaml
```

查看节点自动提供的参数服务：

```bash
ros2 service list | grep robot_config_server_cpp
```

## YAML 参数文件

参数文件基本格式：

```yaml
robot_config_server_cpp:
  ros__parameters:
    robot_name: delivery_robot
    max_linear_speed: 1.0
    safety_enabled: true
```

运行节点时加载：

```bash
ros2 run package_name executable_name \
  --ros-args \
  --params-file config/robot_params.yaml
```

YAML 中的节点名称要与实际节点名称对应，也可以使用通配节点配置。

## 参数描述器

参数声明时可以提供 `ParameterDescriptor`，用于说明参数用途、是否只读和基础范围。

它适合表达单参数约束；模式与速度之间的复杂关联仍应由参数回调检查。

## 参数、话题和服务如何选择

| 需求 | 推荐方式 |
| --- | --- |
| 最大速度、阈值、机器人名称 | 参数 |
| 激光雷达、里程计等连续数据 | 话题 |
| 立即执行一次业务并返回结果 | 服务 |
| 长时间任务、进度和取消 | 动作 |

不要用参数传输高频实时状态。参数更适合“配置是什么”，话题更适合“状态现在是什么”。

## 常见问题

### 参数设置失败，提示类型不正确

检查：

- 参数声明类型。
- 命令行值是否被解析为正确类型。
- Python `Parameter` 是否使用了 `value=`。
- 是否错误地给 double 参数传入整数。

### 参数回调没有执行

检查：

- C++ 回调句柄是否保存为成员变量。
- 回调是否在节点构造后注册成功。
- 修改的是不是正确节点中的正确参数。

### 批量修改后出现部分更新

使用的是普通 `set_parameters()`，或者客户端逐条调用了 `ros2 param set`。有关联的整组配置应通过原子参数服务提交。

### 参数客户端一直等待

检查远程节点名称。参数客户端连接的是节点名称，不是可执行文件名称。

### Python 创建 Parameter 报类型错误

错误形式：

```python
Parameter("car_heights", 2.0)
```

正确形式：

```python
Parameter("car_heights", value=2.0)
```
